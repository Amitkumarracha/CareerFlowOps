# Authorized AWS deployment

These are preparation files. No AWS resources have been created and no cloud deployment has been authorized or attempted.

1. Supply your GitHub repository and push the local commits. Protect `main` and require CI. Configure an AWS GitHub OIDC provider/role with the trust template restricted to your exact repository and main branch. Replace `ACCOUNT_ID` and `OWNER/REPOSITORY`; never use the placeholders literally. Adapt the region in the ECR policy if needed. Create two ECR repositories (`careerflowops-api`, `careerflowops-web`) with immutable tags after authorizing AWS resource creation.
2. In GitHub Secrets, set `AWS_ROLE_ARN`. Set repository variables `AWS_REGION`, `AWS_ECR_REPOSITORY`, `AWS_ECR_WEB_REPOSITORY`, and `VITE_API_BASE_URL` to the actual browser-facing HTTPS origin. Do not put AWS access keys into source. With no role configured, main still runs CI and builds images, and skips ECR publishing.
3. Provision an EC2 instance with sufficient CPU/RAM/disk for CPU embedding inference (start with 2 vCPU/4 GB RAM and at least 20 GB free disk; adjust from observed usage). Install Docker Compose, AWS CLI, Git and Python 3. Use an instance role with ECR pull permissions, not permanent access keys. Limit SSH to your IP or use Systems Manager. Allow 80/443 only when publishing the authorized domain. Keep 5432, 5000, 3000, 9090, 8000 and 5173 private.
4. Check out the exact published Git SHA. Run `python3 infra/scripts/configure.py` once; edit the protected `.env` on the host for production, database password, distinct candidate/admin tokens, correct CORS origin and API base URL. This is a **single-candidate authenticated demonstration**, not a multi-user account platform. Add real identity and role management before multi-user use. Back up PostgreSQL and private data before applying future migrations. The script does not roll back schema changes.
5. Export `API_IMAGE` and `WEB_IMAGE` as complete ECR URIs with the Git SHA tag, and `AWS_REGION`. After deployment authorization, run `bash infra/aws/deploy.sh`. It pulls immutable images, runs migrations and verifies readiness. If your API port differs, also set `API_HEALTH_URL`.
6. To expose the authorized domain with automatic TLS, point DNS at EC2, set `PUBLIC_DOMAIN`, and run `docker compose -f docker-compose.yml -f infra/aws/compose.edge.yml up -d edge`. The frontend must have been built with that HTTPS origin. Keep MLflow/Grafana private through SSH tunnels. No cloud action is automated from this workspace without authorization.
7. For the model workflow, run `make setup && make ml-setup && make reproduce` on an authorized training/development host with access to PostgreSQL/MLflow. Restart the API after alias promotion. DVC's local remote is a demo remote; move it to authorized durable storage before relying on it across machines. No candidate resumes belong in DVC or MLflow.

The EC2 script performs deployment only when invoked by an authorized operator. It does not provision paid infrastructure. Supply account/repository/domain information and authorize those actions separately.

References: [ECR image lifecycle](https://docs.aws.amazon.com/AmazonECR/latest/userguide/getting-started-cli.html), [GitHub OIDC for AWS](https://docs.github.com/en/actions/how-tos/secure-your-work/security-hardening-deployments/oidc-in-aws), [Docker publishing](https://docs.github.com/en/actions/tutorials/publish-packages/publish-docker-images).
